# Candidate: failure-first

## Thesis

Every documented failure in this change's territory is a promise the menu makes that the runtime breaks: a printed keystroke a packaged guard swallows, a search field that walks away from Help, a Dock requirement aimed at a run that owns no Dock tile, an Option chord that composes a character instead of firing, a click handler that guards on a window that is not there, a menu that corrupts while rebuilding under an open mouse, and a range list that drifts from the address it claims to mirror. This candidate designs each item so the failure is foreclosed by construction rather than caught by a test: the packaged build attaches no input guard at all, Help is always the last element of one atomically rebuilt template, the Dock wiring keys off the same activation-policy decision that removed the tile, click handlers structurally cannot see a window argument, repaints only run when the view value changed, and the range vocabulary lives in one contracts module that both the menu and the address schema derive from, so the two cannot disagree. Where construction cannot reach, the design names the exact test layer that pins the behavior, and where no harness can see the failure at all, it says so and schedules a manual check instead of shipping a green test that proves something weaker.

## Concrete design

### Contract changes (`packages/contracts`)

- New `packages/contracts/src/usage-search.ts`: the address vocabulary moves out of the renderer. `usageSearchRanges` as the ordered seven (`1h`, `24h`, `7d`, `30d`, `this-week`, `this-month`, `custom`) and `usageChartMeasures` as the four the chart draws, with their inferred types. This is deliberately distinct from `usageRangeSchema` in `packages/contracts/src/usage.ts`, which is the report-query vocabulary; the two look alike but encode different decisions, so they stay separate per the DRY-for-knowledge rule.
- `packages/contracts/src/ipc.ts`:
  - `canvas:command` gains `zoom-to-100`, `copy-base-url`, and `remove-gateway`. Never `role: 'resetZoom'`, which resets web-contents zoom, not the canvas transform.
  - `usage:command`'s range members derive from `usageSearchRanges` (adding `range-1h`, `range-this-week`, `range-this-month`, `range-custom`), so the enum and the vocabulary cannot drift. The existing pin that `range-90d` throws stays true.
  - New event `app:command` with payload enum `toggle-sidebar` and `toggle-inspector`, answered at the root so a route change never orphans the listener.
  - New report channels `system:sidebar` and `system:inspector`, copying the `system:logs-drawer` shape.
  - The reveal-label table moves beside the `fileBrowser` enum it is keyed on (finder, explorer, file-manager), so the Help menu and the settings surface read one table (AC-H5).
- Type-level spec beside `packages/contracts/src/ipc.test-d.ts`: every member of `usageSearchRanges` has exactly one `range-` command and vice versa, pinned with `expectTypeOf`. The menu-lists-every-range scenario (AC-U3) then holds by construction in both directions.
- `packages/contracts/src/ipc.test.ts` and `ipc-events.test.ts` grow the new channels and members red-first.

### Main-process changes (`apps/desktop/src/main`)

- `windows/dev-window-shortcuts.ts` (new, with spec): dev-only delegation to `optimizer.watchWindowShortcuts`; packaged runs attach nothing. `index.ts:254` calls it, and the same `browser-window-created` block gains the `closed` hook that stands the menu nowhere when the window count reaches zero (failure row 7).
- `windows/renderer-url.ts`: route builders for the three navigation surfaces plus a `gatewaySlugFromUrl` reader beside `onGatewayDetailUrl`. `windows/main-window.ts`: `openGatewaysSurface` (home route, which already lands on the remembered gateway or the empty state, AC-N4), `openProvidersSurface`, `openUsageSurface`, all through the existing `openSurface`.
- `menu/app-menu-template.ts`: `AppMenuItem` gains `enabled`. `AppMenuView` gains `sidebarHidden`, `inspectorOpen`, `standingGatewaySlug`, and the standing gateway's serving flag. The template gains: Help trailing everywhere (recompose Help, Keyboard Shortcuts on `CmdOrCtrl+/` per the Mobbin arm, the config-folder item labeled from the shared table, Report an Issue); View navigation on `CmdOrCtrl+1/2/3`; sidebar on `CmdOrCtrl+B` and inspector on `Alt+CmdOrCtrl+B` (VS Code prior art, keeping Cmd+0 and Alt+Cmd+0 free); the checklist item under View on every platform and out of the app menu; the zoom split with `CmdOrCtrl+0` on `zoom-to-100` and `Shift+CmdOrCtrl+0` on `zoom-to-fit`, Tidy on `Alt+CmdOrCtrl+T`; the Gateway lifecycle group (start, stop, restart on `Alt+CmdOrCtrl` letter chords, a design-review pick), Copy Base URL, and Delete without an ellipsis (AC-S5); the Usage ranges built by one function over `usageSearchRanges`.
- `menu/app-menu-conductor.ts`: `reflectSidebar`, `reflectInspector`, `reflectEngineStates`, all with the equality discipline; `standOnUrl` also extracts the slug. `menu/app-menu-boot.ts` binds `pushAppCommand` and the navigation and help seams; `index.ts` wires lifecycle items straight onto the existing `gatewayLifecycle` from `engine-host/gateway-lifecycle-requests.ts` and the config-folder item onto the same folder derivation `system-ipc` uses.
- Lifecycle enablement law extracted once: `engine-host/lifecycle-availability.ts` (new) answers start, stop, restart availability from `EngineStates` and a slug; `tray/tray-menu-template.ts`'s `gatewaySubmenu` becomes an exported builder over that law with icons optional, and the tray, the Dock, and the app menu all read the one rule.
- Dock (new, `dock/`): a repainter that builds a fresh template from the shared submenu builder (no icons) and calls `app.dock?.setMenu`, installed only when `activationPolicyFor` returned null on darwin. The repaint trigger composes into the existing `repaintStates` callback in `index.ts`, and the stored-gateway read happens once per state change and fans out to tray and Dock rather than reading the disk twice (generalizing `tray/tray-repaint.ts`). The app menu's `reflectEngineStates` joins the same composed callback, so one trigger drives all three surfaces.
- `ipc/register-ipc.ts`, `ipc/system-ipc.ts`, `ipc/dispatch.ts`: the two new report channels wired to the new reflect methods, mirroring `noteLogsDrawer`.
- `apps/desktop/e2e/app-menu.ts`: two new readers, `menuItemEnabled` and `menuItemAccelerator`, since enablement and printed strings are otherwise unreachable from scenarios.

### Renderer changes (`apps/desktop/src/renderer/src`)

- `app/routes/__root.tsx` plus a small route-private hook file: answer `app:command` through the existing `shared/lib/visibility` stores and report `system:sidebar` and `system:inspector` on change, following the `useMenuReadsTheDrawer` pattern. Root-level placement forecloses the dead-listener failure a canvas-scoped sidebar toggle would have on providers and usage routes.
- `pages/gateway-canvas/lib/use-canvas-commands.ts`: the exhaustive `Record<CanvasCommand, ...>` fails the build until `zoom-to-100`, `copy-base-url`, and `remove-gateway` are answered, which is the enforcement point. `zoom-to-100` sets the viewport scale to one; `copy-base-url` reuses the endpoint-box derivation and copy path so the URL rule stays in one place; `remove-gateway` routes through the existing removal flow so the confirmation always appears (the Gateway menu's delete scenario).
- `pages/usage/lib/usage-search.ts`: the vocabulary imports from contracts, everything else unchanged. `pages/usage/ui/usage-page/usage-page-moves.ts`: `RANGE_BY_COMMAND` widens to every range; the `range-custom` command lands the explorer with the range calendar open rather than writing a bare custom range the address parser would bounce to 24h.
- `pages/settings/lib/row-state.ts`: `revealLabelFor` keeps its signature and reads the contracts table.
- `shared/testing/fake-bridge.ts` and the preload bridge plus its declaration file grow the new channels. No new `ui/` component exists in this change, so no story obligation triggers.

### Spec deltas this candidate amends

- The Gateway menu requirement drops renaming (gap resolution below).
- The Dock requirement gains the accessory carve-out: it binds while the app owns a Dock tile.

## The four discovery gaps, resolved failure-first

1. **No gateway rename affordance.** The spec demands the menu land in "the same rename affordance the canvas offers", and the canvas offers none for gateways; the only rename in the slice belongs to virtual models. A Rename item would either invent a new surface, which the proposal's own deferral clause forbids, or point at the wrong affordance, which is the menu-shaped version of a dead keystroke. Resolution: drop Rename from this change, amend the delta requirement, and file a rider issue for the canvas affordance so the menu item lands with it later.
2. **No `engine:restart` channel.** None is needed, and adding one would be the failure. The app menu and the Dock both live in main, where `GatewayLifecycleRequests.restart` already exists with the documented restart-versus-reapply guard; a renderer-side restart channel would create a second restart path whose semantics drift from that guard. Resolution: zero new lifecycle IPC; the menu and Dock consume the same `gatewayLifecycle` seam the tray does, and enablement reads the same extracted availability law.
3. **Dock under an accessory run.** Resolved in failure row 3: the wiring keys off the activation-policy decision itself, the spec gains the carve-out, and the design says plainly that the e2e harness runs in exactly the configuration that has no Dock, so the live-follow scenario is manual by necessity.
4. **Range vocabulary trapped in the renderer.** Resolved by moving the vocabulary to contracts and deriving both the address schema and the `usage:command` members from it, with a type-level bijection spec. The drift failure (menu names a range the address rejects, or the address grows a range the menu misses) becomes a compile error instead of a test that could rot. The report-query vocabulary stays separate on purpose.

## Acceptance criteria: satisfied and dropped

Satisfied, with the layer named in the table: AC-R1 through AC-R3 (R1 manual by necessity, R3 by construction), AC-H1 through AC-H7 (H1 and H4 manual), AC-D1 through AC-D4 (D2's live half manual, D4 via the carve-out), AC-N1, AC-N2, AC-N4, AC-Z1 through AC-Z3 and AC-Z5 (Z3 manual), AC-U1 through AC-U4 (U2's firing half manual, U3 by construction), AC-M1, AC-S1 through AC-S5 (S3 manual regression check).

Consciously dropped or downgraded: the rename half of the Gateway menu requirement (amended out, rider filed), which also mooted the Rename ellipsis clause of AC-S5; AC-N3 stays a non-goal as the reference itself phrases it; AC-Z4's non-US-layout verification is a best-effort manual note because #26907 is closed and its digit behavior is an inference, and no harness or local check can enumerate layouts.

## Risks

- The `Alt` chord family (#45925) is only falsifiable by hand on the target macOS build; the single-builder design makes the fallback a one-line swap, but a late fallback still reprints accelerators the docs or muscle memory may have absorbed.
- The published guide URL for recompose Help and the shortcut reference is unconfirmed; until that page exists the items point at a maintainer-confirmed interim target or the change holds, which is a decision to surface, not to drift into.
- The zoom analysis in failure row 1a contradicts the research brief from the installed source; if the reading is wrong the exposure is a page-zoom double-fire on a packaged canvas, which the AC-Z3 manual check covers before release.
- Placing a reveal-label table in `packages/contracts` stretches that package toward UI vocabulary; the alternative is a new shared package, which is heavier for one table. Named as a tradeoff for the design review.
- The equality discipline on `reflectEngineStates` must compare the derived booleans the template reads; comparing raw state objects would either repaint every push or, worse, never repaint, and the conductor spec pins the derived comparison for that reason.

## Self-score

- Simplicity: 8. The centerpiece deletes a guard instead of adding one, navigation and lifecycle add zero new IPC, and the only new wire surface is one push event plus two report channels copied from an existing shape.
- Spec fidelity: 8. Every requirement lands except renaming, which is amended out deliberately because its target does not exist, and the two scenarios no harness can see are named as manual checks rather than faked green.
- Blast radius: 7. Widening two contract enums deliberately ripples through preload, the fake bridge, and the renderer's exhaustive command map, and the vocabulary move touches the usage page; the ripple is the enforcement mechanism, but it is still a wide diff for a menu change.
