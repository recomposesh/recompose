# Candidate: contracts-first

## Thesis

Every menu behavior that crosses the process boundary derives from a value defined once in `packages/contracts`, and everything that stays inside one process deliberately gets no wire word. The menu template in main and the exhaustive command maps in the renderer are both consumers of the same enums, so the compiler walks every widening to every answer: `use-canvas-commands.ts` already fails the build when `canvas:command` grows a member its `Record<CanvasCommand, () => void>` does not answer, and this design makes that the enforcement mechanism for the whole change. Two vocabularies that today live in the wrong place move into contracts because the menu makes them wire vocabulary: the ledger-range list (module-private in `pages/usage/lib/usage-search.ts` while the Usage menu must name every range) and the file-manager reveal-label table (in `pages/settings/lib/row-state.ts` while the Help menu must print the identical string). The same lens cuts the other way for navigation and gateway lifecycle: no message crosses the wire for either, so neither mints a channel, and the totality specs in `ipc-vocabulary.test-d.ts` pin the absences as deliberately as they pin the presences.

## Contract changes (`packages/contracts`)

### C1. The ledger-range vocabulary lands in `usage.ts`

`packages/contracts/src/usage.ts` gains `usageSearchRangeSchema`, a `z.enum` of exactly `1h`, `24h`, `7d`, `30d`, `this-week`, `this-month`, `custom`, in that order, plus its inferred `UsageSearchRange` type. The order is contractual: it is the Usage menu's listing order, the range popover's listing order, and the accelerator digit assignment. It stands beside, not instead of, the existing `usageRangeSchema` (`24h`, `7d`, `30d`), which names how far back a `usage:report` read reaches; the two are different knowledge and stay two schemas.

Pinned by: a deterministic membership-and-order spec in `packages/contracts/src/usage.test.ts`, and a type-level spec in `packages/contracts/src/usage.test-d.ts` asserting `UsageSearchRange` equals the seven literals while the existing pin that `UsageRange` equals `'24h' | '7d' | '30d'` stands untouched.

### C2. `usage:command` derives its range members from C1

In `packages/contracts/src/ipc.ts`, the `usage:command` payload enum's range members become one `range-<range>` per `usageSearchRangeSchema` member: `range-1h`, `range-24h`, `range-7d`, `range-30d`, `range-this-week`, `range-this-month`, `range-custom`. The four metric members, `toggle-table-twin`, and `refresh` stay as they are.

Pinned by: `packages/contracts/src/ipc-usage.test.ts` rewritten in one batch, keeping the pins that `range-90d` and `metric-errors` throw and adding the law that the enum's range members equal `usageSearchRangeSchema.options` under the `range-` prefix, in order; and a new type-level spec in `packages/contracts/src/ipc.test-d.ts` asserting the extract of `IpcEventPayload<'usage:command'>` matching the `range-` prefix equals the template-literal type built from `UsageSearchRange`. That derived type is load-bearing (it is what makes drift impossible between the range list and the command list), so it earns its `*.test-d.ts` spec under the project's type-level-spec rule.

### C3. `canvas:command` widens by four members

The `canvas:command` payload enum in `packages/contracts/src/ipc.ts` grows `zoom-to-100`, `copy-base-url`, `rename-gateway`, and `remove-gateway` beside the existing five. `zoom-to-fit` keeps its name and meaning; the zoom split is a new member, not a rename, so no existing consumer changes meaning.

Pinned by: `packages/contracts/src/ipc-events.test.ts`, where the two "five acts" specs become nine-act specs, and `packages/contracts/src/ipc.test-d.ts`, where the payload equality spec lists the nine literals.

### C4. One new push event: `view:command`

`ipcEvents` in `packages/contracts/src/ipc.ts` gains `view:command` with payload `z.enum(['toggle-sidebar', 'toggle-inspector'])`. The View menu owns both toggles and the renderer's root shell answers both, so one event carries the pair rather than splitting one menu group across two vocabularies (the sidebar is app-wide, so it cannot ride `canvas:command`).

Pinned by: the event-name table spec in `packages/contracts/src/ipc-events.test.ts` plus a payload membership spec beside it, and the push-vocabulary totality spec in `packages/contracts/src/ipc-vocabulary.test-d.ts` growing to ten events.

### C5. Two new report channels: `system:sidebar` and `system:inspector`

`ipcChannels` in `packages/contracts/src/ipc.ts` gains `system:sidebar` and `system:inspector`, each requesting a strict `{ open: boolean }` and answering `ipcResult(z.void())`, byte-for-byte the shape of `system:logs-drawer` and `system:usage-table`. The renderer reports what the person sees; the menu tick reads the report, never its own last push.

Pinned by: the channel table spec in `packages/contracts/src/ipc.test.ts`, shape specs beside the existing table-twin spec, and the channel-vocabulary totality spec in `packages/contracts/src/ipc-vocabulary.test-d.ts` moving from thirty-nine to forty-one names.

### C6. The reveal-label table moves to contracts

A new `packages/contracts/src/file-browser.ts` exports `fileBrowserSchema` (the `finder` / `explorer` / `file-manager` enum extracted from its inline position in `systemStateSchema`, which then references it) and `revealLabelFor`, the three-string table now living in `apps/desktop/src/renderer/src/pages/settings/lib/row-state.ts`. Exported through `packages/contracts/src/index.ts`. Main's Help menu prints `revealLabelFor(fileBrowserFor(process.platform))` using the existing `apps/desktop/src/main/system/file-browser.ts` derivation; the settings row prints the same call on the reported `SystemState.fileBrowser`. One table, two surfaces, satisfying the byte-identical-label criterion (AC-H5) without a renderer round trip.

Pinned by: a new `packages/contracts/src/file-browser.test.ts` carrying the three label pins that move out of `apps/desktop/src/renderer/src/pages/settings/lib/row-state.test.ts` (the test moves with the knowledge; `row-state.ts` keeps only `launchAtLoginRow`). The `SystemState` pins in `packages/contracts/src/ipc.test-d.ts` stand untouched because the schema's shape does not change.

### Deliberate absences

No `engine:restart` channel and no navigation event. Menu and Dock lifecycle picks run inside main; View navigation runs inside main. The totality specs in `ipc-vocabulary.test-d.ts` enumerate exactly the vocabulary, so both absences are pinned decisions rather than omissions. This deviates from the proposal's Impact wording ("new push commands for navigation... and gateway lifecycle picks") on purpose: the spec's scenarios are about picks landing, and a push command cannot land a pick when no window stands, while the existing main-side seam can.

## How the four discovery gaps resolve

1. **No gateway rename affordance.** `rename-gateway` joins `canvas:command` and its consumer ships in the same change: `GatewayGeneralInfo` gains the rename pattern its model sibling already proves, over the existing `gateways:update` wire word, display name only. The menu item is honest the day it lands because the contract member and its answer land together; if the panel cuts the affordance, the enum member, the menu item, and one spec clause come out together as a stated amendment, never a silent drop.
2. **No `engine:restart` channel.** Resolved by not minting one. Menu and Dock restart run inside main over `GatewayLifecycleRequests.restart`, the seam the tray already trusts; the renderer keeps its start and stop mutations and learns every outcome over the existing `engine:state` push. The contracts lens cuts both ways: what crosses the wire lives in contracts, and what never crosses gets no wire word, with the channel totality spec pinning the absence.
3. **Dock menu under the stays-back accessory run.** No contract change, because nothing crosses the wire: the Dock installer consults `activationPolicyFor` and `app.dock` presence and stands down without erroring. The app-menu delta spec gains one scenario making the accessory exception explicit (the AC-D4 hole closes in the spec rather than in a code comment). The Dock repaint consumes the same `EngineStates` payload the tray repaint consumes, so its enablement law has one home.
4. **The range vocabulary.** Moves to contracts as `usageSearchRangeSchema`; `usage:command` derives its range members from it under the `range-` prefix; main's menu maps the schema options in order, the renderer's popover derives `presetWindows` from the same list, and `movedSearch` maps the commands back. One list, three consumers, and a template-literal type spec that turns any drift into a red build.

Consciously dropped or narrowed: AC-Z4 (non-US layout accelerator printing) and AC-H4 plus the help search-field drift half of AC-H1 stay manual macOS checks with no automated pin, and AC-S3 (menu held open through a rebuild) stays a manual regression check; the design says so rather than writing e2e scenarios that prove something weaker. The proposal's Impact line promising navigation and lifecycle push commands is dropped in favor of the main-side seams, a deviation from the proposal's wording but not from any spec scenario. Mobbin's Cmd+/ convention is kept for the shortcut reference so the binding survives a future in-app overlay.

## Risks

- Moving `UsageSearchRange` into contracts couples a page vocabulary into the shared package: a future renderer-only range then needs a contracts change. Accepted, because the menu made the vocabulary cross-process the moment it must name every range.
- `revealLabelFor` puts printable copy in a wire-vocabulary package. Argued as shared knowledge both processes print; the alternative (a new shared package for three strings) fails YAGNI harder.
- The rename affordance is genuine new surface behavior riding a menu change, the largest single work item here; its cut line is drawn above.
- `Alt+CmdOrCtrl+digit` has a documented macOS flakiness family (electron issue 45925); `CmdOrCtrl+Shift+digit` is held as the fallback pending one manual press test.
- Scoping the keystroke guard to development revives Chromium's own page-zoom keys beside the canvas zoom commands; if a packaged build shows double handling, an owned before-input-event listener blocks only the two page-zoom chords and nothing else.
- The `help` role's search field has a documented history of migrating when menus are inserted ahead of it, and this app splices route-scoped menus per navigation; manual regression, no automated eye exists.
- Widening `usage:command` rewrites several pinned vocabulary specs in one batch, a wide but mechanical test diff that must land as one red-to-green pass.

## Self-score

- Simplicity: 7 of 10. Every mechanism copies a pattern already on disk (one more push event, two report channels shaped like the two that exist, enums widened where enums live), and the two deliberate non-channels delete whole subsystems from the diff, but the rename affordance and the range derivation plumbing are real added machinery.
- Spec fidelity: 9 of 10. Every MUST in both delta specs lands, including every-ledger-range, the byte-identical reveal label, and the accessory-run exception folded back into the spec, with only the criteria no harness can see left to named manual checks.
- Blast radius: 6 of 10. The contract widenings fan out through preload, dispatch, the fake bridge, and both exhaustive renderer maps by design, and that compiler-walked fan-out is the point, but it still touches two packages, roughly two dozen source files, and a batch of pinned vocabulary specs in one change.
