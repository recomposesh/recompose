# Candidate: minimal

## Thesis

Nearly everything the spec deltas ask for already has a working seam on the main-process side of the wire: the menu is built and repainted in main (`conductAppMenu`), gateway start/stop/restart lives in main (`createGatewayLifecycleRequests`, consumed by the tray today), navigate-with-no-window exists as `openSurface` behind `openSettingsSurface`, and the tray already encodes the per-gateway submenu the Dock must mirror. So the minimal coherent shape adds exactly two wire entries (one push event for the sidebar and inspector toggles, one report channel for their ticks), widens the two existing command enums (`canvas:command`, `usage:command`), and answers every other requirement main-side through seams that already exist. The one spec clause with no functionality behind it, gateway rename, leaves scope with a rider, which the proposal's own closing rule licenses: "this change only wires menus and accelerators to functionality the app already has."

## Concrete design

### Contract changes

- `packages/contracts/src/ipc.ts`:
  - `canvas:command` enum grows `zoom-to-100`, `copy-base-url`, `remove-gateway`. The existing `zoom-to-fit` stays and moves to the shifted accelerator; `zoom-to-100` takes `CmdOrCtrl+0`. Never `role: 'resetZoom'`, which resets web-contents zoom, not the canvas transform.
  - `usage:command` enum grows `range-1h`, `range-this-week`, `range-this-month`, `range-custom`, joining the existing three. Seven ranges fit under nine digits, so no accelerator doubling.
  - New push event `view:command` with payload `z.enum(['toggle-sidebar', 'toggle-inspector'])`.
  - New report channel `system:surface-toggles` with request `{ sidebar: boolean, inspector: boolean }`, the sibling of `system:logs-drawer` and `system:usage-table`, but carrying both toggles in one snapshot so it stays one channel.
- New shared value: the reveal-label table (`finder` to "Reveal in Finder", `explorer` to "Show in Explorer", `file-manager` to "Open folder") moves from `apps/desktop/src/renderer/src/pages/settings/lib/row-state.ts` into `packages/contracts` beside `systemStateSchema.fileBrowser`, exported through `packages/contracts/src/index.ts`. Main's menu template and the settings surface both read it, so the label parity the spec demands is one table, not two (AC-H5).
- Spec siblings land red first: `packages/contracts/src/ipc.test.ts`, `ipc-events.test.ts`, `ipc.test-d.ts`. The pinned `range-90d` rejection in `ipc-usage.test.ts` stays green because `90d` remains a non-member.

Wire tally: one new event, one new channel. Navigation, gateway lifecycle, Help, and the Dock cost zero wire changes.

### Main-process changes

- `apps/desktop/src/main/index.ts`: `optimizer.watchWindowShortcuts(window, { zoom: true })` at line 254 runs only under `is.dev`. The dev branch wires F12 and blocks nothing; the production branch is the `before-input-event` guard that eats the printed `CmdOrCtrl+R` and the devtools chord, so a packaged build simply stops registering it and both printed keystrokes fire (the "no dead keystroke" requirement, plus AC-R3 for the devtools row the research found alongside). Zoom keys behave exactly as today, because `{ zoom: true }` already exempted them from the guard. A node-side spec pins that no production path calls `watchWindowShortcuts`; the actual keypress in a packaged artifact stays a named manual check, since `chooseMenuItem` bypasses the input path entirely.
- `apps/desktop/src/main/index.ts` also composes the existing `repaintStates` seam: `repaintTray(states)` plus `appMenu.reflectEngineStates(states)` plus `repaintDock(states)`. No new event plumbing; the engine-state stream already arrives here.
- `apps/desktop/src/main/windows/renderer-url.ts`: three press-stamped route builders shaped exactly like `settingsShortcutRouteFor` (`gatewaysShortcutRouteFor` returns the home route, because `index.tsx` already lands on the last-looked-at gateway or the empty state, which is AC-N4 for free; `providersShortcutRouteFor`; `usageShortcutRouteFor`), plus a `gatewaySlugOfUrl` reader beside `onGatewayDetailUrl` for the conductor.
- `apps/desktop/src/main/windows/main-window.ts`: `openGatewaysSurface`, `openProvidersSurface`, `openUsageSurface`, each one line over the existing `openSurface`. That function already creates a window when none stands and never reads a `browserWindow` click argument (AC-N1, AC-N2).
- `apps/desktop/src/main/menu/app-menu-template.ts`, the single file every item lands in:
  - `AppMenuItem` grows `enabled?: boolean` (disabled, never hidden: a hidden item's accelerator can still fire on macOS, a disabled one cannot).
  - Help menu with `role: 'help'` appended after `{ role: 'windowMenu' }` on every platform, no accelerator on the top-level item: "recompose Help", "Keyboard Shortcuts" on `CmdOrCtrl+/` (the settled binding per the Mobbin arm), the config-folder item labelled from the shared table via the existing `fileBrowserFor(platform)`, and "Report an Issue".
  - The checklist item moves under View on every platform: delete the `checklistToggleItem` call from `macApplicationMenu` and drop the platform branch in `viewMenu`.
  - View gains the three navigation items on `CmdOrCtrl+1/2/3` in spec order (gateways, providers, usage) and the two checkbox toggles: sidebar on `CmdOrCtrl+B`, inspector on `Alt+CmdOrCtrl+B` (the VS Code pair the research recommends), the inspector item `enabled: view.onGatewayDetail`.
  - Gateway menu gains the lifecycle group (start, stop, restart) mapped from the shared lifecycle items (below), "Copy Base URL", and "Delete Gateway" with no ellipsis (the confirmation dialog carries the ask, AC-S5). The zoom group splits: "Zoom to 100%" on `CmdOrCtrl+0` sends `zoom-to-100`, "Zoom to Fit" moves to `Shift+CmdOrCtrl+0`, Tidy takes `Alt+CmdOrCtrl+T`. Lifecycle accelerators are proposed as `Alt+CmdOrCtrl+S` (start), `Alt+CmdOrCtrl+X` (stop), `Alt+CmdOrCtrl+R` (restart) and are a design-phase pick with no structural weight.

- `apps/desktop/src/main/menu/app-menu-conductor.ts`: `AppMenuView` grows `standingGatewaySlug`, `gatewayServing`, `sidebarShown`, `inspectorShown`; `standOnUrl` also parses the slug; new `reflectEngineStates` and `reflectSurfaceToggles` sit beside `reflectLogsDrawer`. The single rebuild path stays the only state, as the file's own `@summary` records.

### Spec-delta amendments this candidate carries

- `openspec/changes/app-menu-shortcuts/specs/app-menu/spec.md`: drop the rename clause from the Gateway requirement (rider below); add one sentence to the Dock requirement excluding a stays-back accessory run, which has no Dock tile to hang a menu on.

## How each discovery gap resolves

1. **No gateway rename affordance exists** (`GatewayGeneralInfo` takes only `{ gateway }`; the only `onRenamed` in the slice belongs to virtual models). The spec says the menu must land "the same rename affordance the canvas offers", and the canvas offers none, so a menu item here would need a new canvas surface, which the proposal explicitly defers everything like. Minimal resolution: cut rename from the spec delta and park it as a rider issue ("gateway rename affordance on the canvas, then a Gateway menu item over it") under the repo's existing `rider` label. This is the honest answer, not a punt: every other Gateway item wires to something that exists.
2. **No `engine:restart` channel exists.** None is needed. The Gateway menu is built in main, and `createGatewayLifecycleRequests` in `apps/desktop/src/main/engine-host/gateway-lifecycle-requests.ts` already exposes `restart` (the tray uses it today). Boot hands the same value to `bootAppMenu` and to the Dock. The renderer still sees every state change over the existing `engine:state` push, so its query cache follows without being asked.
3. **The Dock menu in a stays-back accessory run.** `activationPolicyFor` makes a darwin run under `RECOMPOSE_WINDOW_STAYS_BACK` an accessory, and an accessory has no Dock tile. The requirement as written has no exception, so the candidate amends the spec delta with the exclusion and guards the wiring on `staysBack(process.env)`, alongside the `app.dock?.` optional chain that already covers non-darwin.
4. **The ledger-range vocabulary trapped in a renderer slice.** `USAGE_SEARCH_RANGES` stays module-private where it is; the widened `usage:command` enum in `packages/contracts/src/ipc.ts` becomes the wire's single range vocabulary, exactly as the code map suggests. Main builds the menu from the enum it already imports; the renderer's `RANGE_BY_COMMAND` answers it; a spec pins the bijection between the enum's range members and `PresetRange` plus `custom`. No new shared module, no renderer import from main, no third copy of the list. Labels stay per-surface, which is today's standing (the menu already prints "Last 24 Hours" where the popover prints "Last 24 hours"): two casings for two surfaces is presentation, not duplicated knowledge.

## Acceptance criteria: satisfied and dropped

Satisfied by construction: AC-R1, AC-R2, AC-R3 (guard absent in production, roles keep their live accelerators); AC-H2, AC-H3, AC-H5, AC-H6, AC-H7 (Help shape, shared label table, same `openPath` act); AC-D1, AC-D2, AC-D3, AC-D4 (Dock wiring, rebuild-per-change, placeholder, accessory exclusion); AC-N1, AC-N2, AC-N3, AC-N4 (openSurface reuse, home route's remembered-gateway landing); AC-Z1, AC-Z2, AC-Z3, AC-Z5 (four distinct zoom items, `zoomTo(1)`, unchanged page-zoom behavior, Tidy accelerator); AC-U1, AC-U3, AC-U4 (Alt spelling, all seven ranges, plain digits reassigned); AC-S1, AC-S2, AC-S4, AC-S5 (disabled not hidden, report-then-repaint ticks, fresh templates, no ellipsis on Delete); AC-M1 (standard shape, checklist out of the app menu).

Consciously dropped or reduced:

- The rename half of the Gateway requirement: cut with a rider, as above.
- AC-Z4 (non-US layout accelerator printing), AC-S3 (menu held open through a rebuild), AC-H1 and AC-H4 (the macOS Help search field surviving route-scoped menu splicing): manual macOS checks named in the design, because no harness in this repo can see a native menu or a keystroke. AC-U2's Alt+digit press test likewise, with `CmdOrCtrl+Shift+<digit>` held as the recorded fallback if Option digits prove flaky.
- The packaged-build reload press itself: proven by the node spec over the guard wiring plus one manual press on a packaged artifact, never by a green `chooseMenuItem` click that bypasses the input path.

## Risks

- Dropping the production `watchWindowShortcuts` call un-blocks `CmdOrCtrl+R` for everyone, including a person mid-edit on the canvas; the app persists state continuously, so a reload is cheap, but the design should say so rather than discover it.
- Alt+Cmd+digit has a documented flakiness history on macOS layouts (electron#45925); the fallback chord is named above and costs one template edit if the press test fails.
- The Help search field migrating on menu splice (electron#4479) is adjacent prior art: this app inserts Gateway and Usage before Help on every route change. Full-rebuild-then-set is not the reported trigger shape, but the manual walk (gateways to usage and back, then search) guards it.
- `canvas:command` grows toward a general gateway command bus (`copy-base-url`, `remove-gateway` are not strictly canvas acts). At three added members the single channel is still the simplest honest shape; if a later change adds more gateway acts, renaming the event is a contracts-only refactor.
- The Dock repainter re-reads stored gateways beside the tray's own re-read on every state change: two cheap disk reads per change, each surface keeping the "never show a gateway the disk no longer holds" invariant independently.
- The published guide and shortcut-reference URLs are unconfirmed; if no shortcut page exists yet, both Help items open the guide and the reference item's dedicated target becomes part of the docs work, not this change.
- Navigation lands through the `openSurface` hash write; the `at` search param is proven on the home and settings routes, and the providers and usage routes must tolerate it (TanStack search validation there needs a look before the route builders settle).

## Self-score

- **Simplicity: 9/10.** Two new wire entries total, zero new channels for navigation, lifecycle, Help, or the Dock, and every handler terminates in a seam that already exists; the only new abstractions are one extracted enablement law and one URL helper.
- **Spec fidelity: 8/10.** Every requirement is met as written except the rename clause, which is cut openly with a rider, and the accelerator-fires-in-packaged-build family, which no candidate can automate and this one pins as narrowly as the harness allows.
- **Blast radius: 7/10.** Roughly two dozen production files change, but almost all additively along existing patterns; the only behavior removals are the production input guard and one app-menu row, and the contracts enum widening is compiler-enforced at every consumer before it ships.
