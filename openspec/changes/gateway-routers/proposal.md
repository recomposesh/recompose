# Gateway routers design

The gate-1 design document for the gateway-routers feature, amended from the entry proposal on 2026-08-14.

## Why

A virtual model reaches exactly one target today, so a person who pooled several accounts under one name gets no benefit from the pool. The account that hits its limit takes the request down with it. The Architecture Decision Record (ADR) that deferred routing, ADR-0081, named the two modes that open the feature: `failover` and `round-robin`. This change ships them.

The field supplies the bar, because the pinned upstream's open defects show what a naive router does. A silent transport failure skipped failover entirely (CLIProxyAPI#2189). Rotation broke chained turns (#2594, #3189). One exhausted credential poisoned a whole pool (#3317). Every decision below makes one of those failures impossible or immediately legible.

## What changes

The maintainer locked the eighteen decisions below. The delta spec freezes them as requirements.

1. **Routers chain.** A router's child may be a target or another router. `README.md` line 30 already promises "Chain routers to combine strategies," so composition is product identity rather than roadmap.
2. **A virtual model binds either kind.** Its binding may be a target directly or a router. The cable from a virtual model node may meet a target card or a router card, and the same holds for a router's children.
3. **Both modes ship, and no other.** `failover` walks its children in declared order, and `round-robin` spreads eligible requests across them. The modes in issues #33, #43, #44, #45, #46, and #47 stay in their issues, per ADR-0081.
4. **The stored shape is an id-keyed node table, not a recursive schema.** A virtual model binds `routing: { entry: nodeId, nodes: Record<nodeId, routeNode> }`. A route node is a discriminated union of a target arm and a router arm, and a router names its children by id. Decision 2 falls out for free: the entry node is of either kind. The session spike proved why flat wins. On the pinned `zod` 4.4.3, a recursive getter union under `z.discriminatedUnion` still raises ts7022, ts2615, and ts2345, and cyclic input overflows the stack with a RangeError. String references make a parsed cycle structurally impossible. Acyclicity plus dangling-reference validation is one visited-set walk in a `superRefine`, in contracts, ahead of any canvas guard, per ADR-0081 rule 3. Deferred modes enter later as arms of a `policy` union rather than a second migration.
5. **The gateway config takes version 3.** The migration rewrites a stored direct target into the one-node graph that serves identically. It registers beside the existing entry in `packages/contracts/src/gateway-config.ts`, and `packages/contracts/src/gateway-config-migration.test.ts` proves the round trip. One representation means no direct-or-graph union, so no document can stand half migrated.
6. **The engine child picks the child, and main keeps every account.** A route node id crosses to the child as a seat name. `accountId` never crosses, so the assertion at `packages/contracts/src/engine-protocol.test-d.ts:152` stands. The spend request and `SpendGrantFor` grow the route node id, and a grant resolves per attempt. Only main turns a seat into a credential, ADR-0081 rule 4 verbatim. A missing credential on one child becomes a per-child outcome inside the walk, so one bad credential never poisons a sibling (#3317).
7. **The classification table lives in the engine.** One pure module with one consumer; contracts placement would buy a hypothetical second reader. Its rows are data, pinned by a deterministic spec and a property test with a deterministic twin. Inputs arrive normalized by `packages/engine/src/plugin-abi.ts` and `packages/engine/src/subscription/codex-errors.ts`, so the table never re-parses a vendor body. Context-length failures stay request-scoped per ADR-0081 rule 8, and a bigger-window fallback category stays out, named here so the omission reads as a decision.
8. **The commit boundary is the first byte written downstream, never an upstream 200.** Before it, an upstream `event: error`, a transport failure with no status, and a retryable status all move to the next child. After it, the provider's stream error forwards verbatim, the stream closes, and no other child begins. Anthropic documents that a 200 stream can open with an overload error, so the upstream status proves nothing. Holding relay until the first upstream event classifies isn't buffering. The seam is `translatedStreamBody` in `packages/engine/src/gateway-stream-answers.ts`.
9. **A transport failure with no status is retryable.** Today `reachedUpstream` in `packages/engine/src/gateway-proxy.ts:256` swallows every non-`InvalidJsonBodyError` failure into `null`, which becomes a terminal answer. That's the shape of #2189, where failover never fired because a status-less failure matched no status list. It becomes a typed transport outcome, constructed before any status logic runs, so exhaustiveness is compiler-checked.
10. **Termination is structural.** A request-scoped visited set of attempted node ids plus a bounded attempt cap, so no configuration turns one client request into an unbounded upstream sequence. A counter can reset, which is how litellm#7091 looped forever. A visited set can't.
11. **Cooldown keys by route node id, lives in memory, and flushes on restart.** Duration comes from the provider's own signal when one arrives: `Retry-After` as delay-seconds or an HTTP-date, or the Anthropic reset headers. Otherwise one fixed default applies. No failure counting in this release. Two of #3317's suspected causes were health state that outlived its trigger, so a restart must forget everything.
12. **Three new refusals.** An empty router. An exhausted router that enumerates every child attempted with its reason and carries the earliest retry time. A chained turn refused under round-robin. `RenderedRefusal` in `packages/engine/src/refusal-wire.ts:43` carries only `{status, body}` today, so the exhausted refusal widens that type with an optional retry-time field. `refusalResponse` in `packages/engine/src/gateway-wire.ts` writes the `Retry-After` header from it, as delay-seconds, at the one place a rendered refusal becomes a `Response`. The retry time is a fact of the refusal, not of the dialect, so it rides the rendered value rather than scattering header writes.
13. **A chained turn never rotates.** A request carrying `previous_response_id`, or replaying encrypted reasoning or thinking signatures, answers the typed refusal under round-robin rather than moving to another account. The feature builds no affinity map: session affinity is issue #45 and stays deferred. This is a live configuration, not a hypothetical. recompose serves `/v1/responses` and `/responses` downstream (`packages/engine/src/gateway-route-paths.ts:9`) and forwards `previous_response_id` (`packages/engine/src/dialect/responses-request-options.ts`). Silent rotation reproduces #2594's `400 "No tool call found"`. Failover still serves a chain in declared order, and a mid-chain failover can poison encrypted reasoning (#3189). The router ADR records that residual and defers it to #45.
14. **Attribution covers every attempt.** One request touching two targets paints both cables: the failed child's cable shows its outcome while the answering child's shows success. The traffic report grows route node identity, so `NoteTraffic` in `packages/engine/src/gateway-traffic.ts` says which node each attempt touched. `logRowSchema` already carries `accountId` and `providerModel`, so log rows attribute attempts without a shape change. A router that hides failed attempts hides real spend.
15. **The serving-path end-to-end (e2e) suite adopts AIMock.** `@copilotkit/aimock` declares `license: "MIT"` with zero runtime dependencies, pinned exact, one instance per worker on an ephemeral port spawned in Playwright global setup. Deterministic controls only: `nextRequestError`, fixtures with `sequenceIndex`, `truncateAfterChunks`, and `disconnectAfterMs`. A chaos rate is 0 or 1 and never a value between, because the rate is a threshold on a random roll and only those two settle it. `disconnectRate: 1` is the one expression of a connection dropping before any status, and it still journals the request. Two verifications ride before merge: that a 429 can carry `Retry-After`, and the 400 malformed shape. The recorded risk: a four-month-old single-vendor package at 31 releases in those four months. This answers rider #140, which asked for the decision with an ADR either way, and the ADR lands with the implementation.
16. **Four rider items fold into this train.** From #155: the credential refusal learns to name where in the chain it stopped rather than only the gateway (`packages/engine/src/refusals.ts`), the `withXaiRetryAfter` rename in `packages/engine/src/provider/xai-response.ts`, and the failure reveal anchoring below the chip with no flipping (`apps/desktop/src/renderer/src/pages/gateway-canvas/ui/cable-failure-chip/cable-failure-chip.tsx`). From #154: the furniture-scenario amendment in `apps/desktop/e2e/features/gateway-canvas/furniture.feature`, which opens on its own once a composition carries a router. Retry-after is the signal the cooldown model consumes, and the new cables give the chip new anchor positions, so every item sits on a file this change already opens.

17. **A router isn't a card.** Every other node on the canvas is a rounded rectangle, and a router isn't a thing a person stored. It carries the same four-slot grammar inside a chamfered frame whose left and right edges come to a point, so a cable meets the point rather than a flat side. The footprint stays 184 by 88, so the column pitch and the row rhythm don't change. The design file draws two rejected alternatives beside it: a decision diamond, which reads instantly but costs a column of width once its label sits beside it, and a capsule, which is the smallest mark but leaves no room for the name.

    The frame draws its border twice: two concentric lines of equal weight in the role tint, the outer on the edge and the inner 5 pixels inside. No other node draws a second line. The alternatives were unavailable rather than merely worse, and the `node-card` utility in `apps/desktop/src/renderer/src/app/styles/theme.css` says why. A tinted fill is the interaction language rather than a kind. Hover and focus mix the tint at 8 percent, selected at 12 percent with a glow ring, pressed at 14, and selected while hovered at 18. A router resting at any of those percentages would wear a state it isn't in. A dashed outline already means draft or removed. The border weight is 1.5 pixels, which is what the utility sets, so the router matches every other card there.

    On the tint itself: no free hue exists. Every ramp in `primitives.css` carries a meaning, and the system already shares hues across surfaces, since `--color-series-slot-4` is the gateway teal and `--color-series-slot-5` is the pink a virtual model wears. Indigo carries `--color-series-input` and `--color-series-slot-1`, which render only in `shared/ui/series-chart` and the usage page. A router and an indigo bar never share a screen, which is the same guarantee teal and pink already rely on.

18. **One ask names the two kinds.** A cable dropped on empty canvas, from a virtual model or from a router, asks what to bind before anything else: a router, or a target. Picking the target continues into the account and model pick that ships today. Picking the router drops a router node, already wired, holding no child. The same ask serves a router's next child, so one gesture reaches a nested router rather than two. A draft virtual model asks it too, so a person finishes the draft without a detour.

## The picked approach

Three candidates competed in `discovery/`: minimal, failure-first, and contracts-first. Contracts-first won, and each loser left required pieces behind.

**Contracts-first, picked.** It won on migration safety and future-mode fit, the two axes it self-scored highest, and the session spike converted its premise from claim to proof. The id-keyed node table doesn't mitigate the `zod` recursion hazard. It deletes it, and keeps the chaining the product sells. One representation per rule follows: a direct target is the one-node graph, and the deferred modes are future `policy` arms. Children held as id references are the seam where #43's weights and #45's affinity hints later attach. Its honest price is shipping speed and test cost: every stored-target reader changes now, and both protocol type-spec suites rewrite. The maintainer paid that price because each touch tracks a real contract change, and the alternative was paying it later under a second migration.

**Minimal, rejected on its one structural claim.** It proposed cutting nested routers to delete the recursion hazard and halve the surface. The spike deleted the same hazard without cutting the feature, and `README.md` line 30 makes chaining product identity, which the candidate's own five-of-ten future-fit score conceded. Two of its judgments survived into the locked list. The classification table lives in the engine because it has one consumer (decision 7), and a chained turn refuses rather than pins (decision 13).

**Failure-first, rejected on its state.** Its response-id map pinned chained turns to their serving child through a bounded in-memory cache. That builds a corner of sticky routing ahead of its feature. It invents an affinity key, an eviction policy, and a restart story here, only for #45 to re-cut them. The refusal keeps one representation of who owns affinity, which is nobody yet. Everything else it argued from the defect list stands in the locked set. Decision 8 takes its commit latch at the first downstream byte. Decision 9 takes the typed transport outcome that makes #2189 unmissable by construction. Decision 10 takes the visited set that makes #7091's loop impossible to write, and decision 12 takes the exhausted refusal that enumerates every child. Its proof scenarios, one per shipped defect, carry into the delta spec at the freeze.

## The router inspector

Selecting a router opens the inspector headed by the node's kind, through the shipped subject dispatch in `ui/gateway-drawer/gateway-drawer.tsx`. The mode control sits at the top of the panel and the children stack below it, the layout the OpenAI Platform reference draws. The control reuses the shared `SegmentedControl` (`apps/desktop/src/renderer/src/shared/ui/segmented-control/segmented-control.tsx`). Under failover the child list reads as a ladder. Each row always carries a printed rank number, the child's name, and a drag handle, per the WorkOS and Monarch references in `discovery/mobbin-references.md`. The move up and move down buttons reveal under hover and keyboard focus, the way `ui/node-card/node-card.tsx` already reveals its keyboard ask. A two-child ladder then doesn't wear four buttons that mostly do nothing. A sentence above the list says which end wins, and it changes with the mode rather than sitting as fixed helper text. Under round-robin the same list stands unordered, and one sentence names the prompt-cache cost of rotation at the point of choice.

## Design-system gap analysis

The shipped canvas vocabulary carries most of what the router needs. `apps/desktop/src/renderer/src/pages/gateway-canvas/lib/node-graph.ts` holds the node union the `router` kind joins, and the card builds from the `node-card` recipe the target card already wraps (`ui/node-card/`, `ui/target-node/target-node.tsx`). Cables to and from a router paint through `lib/cable-standing.ts` unchanged. The drop-picker (`ui/drop-picker/drop-picker.tsx`) gains a router as the third thing a released cable can meet, and `ui/subject-bodies/subject-bodies.tsx` gains the `routerBody` sibling. `lib/log-scope.ts` mirrors the fourth subject kind.

A design-critic pass measured four claims this document made before the gate, and three fell. The corrected picture:

- **The design system must author the role tint, and it can't be orange.** The archived canvas decision 13 reserved orange for the router, but the reservation never minted a token. `theme.css` holds no `--color-router`, so `node-tint-router` resolves to nothing and the card falls back to the accent blue that virtual models already wear. Two tokens already spend orange: `--color-warning` at line 50 and `--color-cable-draft` at line 80 both resolve to it, so a router frame in orange reads as a draft cable. The design project "recompose-design-system" authors a `--color-router` and `--color-router-ink` pair on a free hue, the way `--color-gateway` carries its ink sibling, before implementation starts.
- **The chamfered frame is a new shape in the vocabulary.** Decision 17 fixes it, and the design file draws it beside the two rejected alternatives. It needs authoring in the design project as a node treatment, because no shipped node departs from the rounded rectangle. Its ports sit on the two points, so `lib/cable-standing.ts` keeps its anchor math.
- **The router card keeps one outgoing port, not one per child.** The WRITER reference fans out per child, but the shipped card is 88 pixels of right edge (`h-22 w-46`) against a 24 pixel hit target, so the fourth port has nowhere to sit. Archived decision 12 also puts the add affordance on every source port, so a port per child would leave no port for adding a child. The card carries the single port `virtual-model-node.tsx` already has, and the ladder's order reads in the inspector rather than off the card edge.
- **The mode reads in the mono subtitle, not in a new pill.** The card grammar holds a kicker chip, a type label, a name, and a mono subtitle documented as the identifier or the standing. `failover` and `round-robin` are lowercase machine vocabulary, which is exactly what that line carries, and the kicker row has around 90 pixels left, which `round-robin` overruns. No new element, no new token.
- **The ordered child list is genuinely new.** No shipped row carries a rank, a drag handle, or reorder buttons, and `ui/option-list/` is a picker rather than a ladder. A new `ui/` component folder owns the row and ships its stories sibling, per the component-folder rule.
- **The cooling state rides the child card, not the router.** It reuses the shipped chip grammar of `ui/cable-failure-chip/cable-failure-chip.tsx` tinted with the existing `--color-attention` pair, reading "Cooling, 2 min" and stepping at a human cadence so the state is text rather than animation. At zero it reads "Ready," which claims eligibility and never health.

The layout isn't free either. `lib/tidy-layout.ts` holds `COLUMN_OF_KIND` as a closed record of gateway, model, and target, so no column stands reserved. Seating the router moves targets to the third column, which moves every stored position, and `targetSeatBeside` and `seatForNewNode` both assume a target sits exactly one column pitch from its model. This change rewrites those helpers, states how a router's children group on adjacent rows so cables don't cross, and migrates stored positions.

## The accessibility contract

The shipped canvas requirement holds: every drag gesture keeps a single-pointer and keyboard twin, per Web Content Accessibility Guidelines (WCAG) 2.2 success criterion 2.5.7. This feature adds two gestures.

**Wiring a router.** The cable drag that binds a virtual model to a router, or a router to a child, keeps the shipped twin. The plus affordance and the picker create every binding a drag can, and both now open on decision 18's ask. The keyboard path therefore reaches a router exactly where the pointer does. The live region announces the outcome as it does today.

**Reordering a failover ladder.** This gesture is new. The Mobbin arm found no reference that reorders inline on a canvas. Every reference reorders in a panel. So the canvas never hosts the reorder gesture, and the inspector's child list owns it. The drag handle serves the pointer. The move up and move down buttons on each row are both the single-pointer twin and the keyboard path. A row context menu carries the same two commands, per the macOS Human Interface Guidelines. The buttons sit in the tab order, and moving a row keeps focus on the moved row's control. The live region announces the new rank, as in "second of three." The printed rank number lets the result read without counting rows. Every handle and button keeps the 24 pixel hit target the shipped contract requires.

The cooling state binds here too: its countdown reads as text beside the tint, so the state never rests on color alone.

## Capabilities

### New capabilities

- `routers`: the behavioral contract of a router node, its two modes, its health and cooldown model, and the failures that permit another attempt.

### Modified capabilities

- `virtual-models`: a definition binds a target or a router, and a refusal now names where in the chain it stopped.
- `gateway-canvas`: the canvas renders router nodes between a virtual model and its targets, a cable may meet a router, attempts paint per cable, and the reorder gesture joins the accessibility contract.

## Impact

**Contracts** (`packages/contracts/src/`). In `gateway-config.ts`, the virtual model's `target` becomes the `routing` node table, `GATEWAY_CONFIG_VERSION` moves to 3, and the visited-set walk validates acyclicity and dangling references at parse. The migration registers through `migration.ts` beside the existing entry, and `gateway-config-migration.test.ts` proves a version-2 document serves identically. In `engine-protocol.ts`, the engine's view mirrors the table with `accountId` erased, the spend request grows the route node id, and the traffic report grows per-attempt node identity. The type-level specs rewrite exactly where the contracts change, which the invariant permits, and `engine-protocol.test-d.ts:152` stands untouched. `engine-logs.ts` doesn't change.

**Engine** (`packages/engine/src/`). A new pure classification module holds the outcome table as data, mutation-gated with a property test and its deterministic twin. `gateway-proxy.ts` gains the attempt walk and the route node id on `SpendGrantFor`, and its catch-and-null becomes the typed transport outcome. `gateway-request-crossing.ts` resolves the graph entry and detects a chained turn. `gateway-stream-answers.ts` gains the commit latch. `refusals.ts` gains the three refusal arms, and `refusal-wire.ts` widens `RenderedRefusal` with the optional retry time. `gateway-traffic.ts` carries node identity. The side paths that read the single target directly, among them `gateway-count-tokens.ts` and `gateway-images.ts`, resolve through the one shared rule the first open question names. `provider/xai-response.ts` takes the #155 rename.

**Main** (`apps/desktop/src/main/`). `engine-host/stored-gateway.ts` builds the engine view node by node, erasing accounts. `engine-host/spend-grant.ts` resolves a grant per attempted node rather than once per request. `storage/gateway-store.ts` persists version-3 documents, and the newer-schema guard keeps its shape.

**Renderer** (`apps/desktop/src/renderer/src/pages/gateway-canvas/`). `lib/node-graph.ts` gains the router kind and keys its traffic memory per route node, so the existing `failed` and `served` standings paint per attempt. `lib/model-draft.ts` writes bindings into the graph. `lib/tidy-layout.ts`, `lib/log-scope.ts`, and `model/served-models.ts` learn the fourth kind. The `ui/` segment gains the router node and child-list folders with their stories siblings, and `drop-picker`, `subject-bodies`, `gateway-drawer`, and `cable-failure-chip` change as the gap analysis names.

**Tests.** `apps/desktop/e2e/features/virtual-models/targets.feature` and `apps/desktop/e2e/features/gateway-canvas/cable-wiring.feature` grow router scenarios, `furniture.feature` takes the amendment from #154, and AIMock enters Playwright global setup beside the stubs in `apps/desktop/e2e/key-probe-stub.ts` and `apps/desktop/e2e/runtime-stub.ts`.

**Migration story.** A stored version-2 gateway rewrites each direct target into the one-node graph whose entry names it. Nothing else changes, and the gateway serves exactly what it served before. Because no direct-or-graph union exists, a half-migrated document is impossible to represent, and the round-trip spec pins the equivalence.

**Decision records.** Two ADRs land with the implementation: the router design record carrying the residuals this document names, and the AIMock adoption record rider #140 asked for.

## Open questions for gate 2

1. **The side-path rule.** Token counting, images, and the other non-serving paths read one provider model today. Which child does a router-bound model resolve for them? The candidate answer is the first declared child, decided once and recorded in the router ADR.
2. **The two numbers.** Decision 10 locks the attempt-cap mechanism and decision 11 locks the cooldown mechanism, and neither locks its number. The field's defaults tune replica fleets, not a person's metered accounts, so both numbers are decisions to record rather than values to cite.
3. **Round-robin cursor semantics.** Where the cursor keys, and whether a cooling child consumes its turn. The research recommends filtering before selection, so live children keep alternating evenly, and keying by resolved router identity per ADR-0081 rule 6. The spec freeze writes both down.
4. **The exhausted refusal's status.** The candidate mapping is 429 with `Retry-After` when every child carries a retry time, and 502 otherwise. The freeze fixes the mapping and the refusal copy, including the remedy sentence the chained-turn refusal offers.
5. **The streaming scenario split.** The delta spec's single scenario for a failure after streaming began collapses three cases the commit boundary separates: a pre-commit stream error, a post-commit stream error, and a status-less transport failure. The freeze splits it into three, as the acceptance arm recommends.
6. **What names a router.** `NodeCard` demands a name, and nothing names a router today. Either the mode names it, or a person does, or it takes a derived name from what it holds. The freeze picks one, because the drop-picker and the inspector both need it.
7. **An incomplete router before its first request.** A router holding no child, or one child, saves without complaint and refuses only when a request arrives. The candidate answer gives it the dashed ghost treatment the removed target already wears, so the canvas says it at compose time. The freeze decides that, and it decides whether a person can undo a reorder, since archived decision 9 deferred undo for the whole canvas.
