# Brainstorm decisions

Locked with the maintainer on 2026-08-10, standard tier, after the discovery arms and the Mobbin pass. Fifteen decisions.

1. **Cost leaves this slice.** No dollar cell anywhere: the footer's left group ends at tokens per minute. The price-table source and the subscription-estimate labelling questions move to a later feature. (The repository holds no price table, and subscription accounts have no per-token price; any figure would be an estimate at list rates.)
2. **A client is a distinct source.** The client count reads distinct request sources, keyed by IP address plus user agent, seen inside the rolling window. No dependency on a gateway auth layer.
3. **Every aggregate rides one rolling 60-second window.** Requests per minute, tokens per minute, the client count, the error count, and p95 latency all compute over the same window. p95 is an exact selection over the window, never a sketch. An empty window reads zeros; the footer never blanks.
4. **The errors segment hides at zero.** No errors, no segment; above zero it appears in the danger tint. Its arrival is itself the signal, matching the reference screenshots.
5. **The node and wire tally comes from `canvasGraph`.** The derived graph in `pages/gateway-canvas/lib/node-graph.ts` is the one honest source for the footer's right side.
6. **The observation is the row (architecture A).** `ProviderRequestLog` gains the gateway slug and the virtual model id, so one `ProviderObservation` carries the whole log row with no correlation state. A wall-clock stamp joins at publish time, because `startedAt` is monotonic. The telemetry feed attaches through the non-destructive `subscribe()`; it never calls `popOldest` or `clear`, which the management usage queue drains destructively. Rows leave the engine child over the existing report path, the main process coalesces them on the established 16 ms cadence, and a new `engine:logs` push channel delivers an initial backfill on subscribe followed by bounded append batches.
7. **The renderer computes the footer aggregates from the same rows.** One source feeds both surfaces; no second metrics contract.
8. **Chips are the selection, one mechanism.** A virtual model chip and that virtual model's canvas node select the same subject: pressing the chip selects the node, selecting the node lights the chip. The All chip is the gateway scope. The Errors chip is an independent extra narrowing that composes with whatever scope stands. A selected target shows a transient chip carrying its name for as long as the selection holds.
9. **Selection scopes the rows.** The gateway shows everything, a selected virtual model shows the requests that passed through it, and a selected target shows the requests that reached it.
10. **Rows read newest at the top, with deep history.** The drawer keeps up to 10,000 rows, matching the engine ring buffer, behind a virtualized list. TanStack Virtual enters as a new dependency (nothing installed covers virtualization; the house already rides the TanStack stack). Row keys are stable identifiers, never indexes. The list follows the newest row only while the viewport rests at the top.
11. **The drawer height drags and is remembered.** The existing panel machinery extends to the drawer: `panelBounds` gains a drawer entry beside the inspector, and the persisted-width pattern carries the height across sessions.
12. **The drawer is a non-modal disclosure.** The canvas stays live under it, selection keeps working, focus is never trapped. A visible, keyboard-reachable close control sits in the drawer. A visually hidden polite live region announces appended rows beside the virtualized list, because `role="log"` and virtualization conflict. WCAG 2.2 SC 2.4.11 (focus not obscured) binds the overlay.
13. **No prompt or completion bodies ever ride in a row.** The existing privacy rule on `requestOutcomeSchema` extends to the log stream: failures carry status-derived sentences only.
14. **Copy names the alias a virtual model, never a bare model.** A Live indicator sits beside the drawer title while the stream stands connected, following the Vercel and Profound pattern from the Mobbin pass.
15. **Naming avoids two collisions.** The new footer is not `status-bar` (taken by the app-wide widget) and not `toolbar-footer` (taken by the start-failure line). The new drawer is not `gateway-drawer` (taken by the right-side inspector). Final names land in the gate-1 design document.

The footer stays the one entry point to the drawer: a click opens it, the affordance is keyboard-reachable, and the idle footer reads zeros rather than hiding.
