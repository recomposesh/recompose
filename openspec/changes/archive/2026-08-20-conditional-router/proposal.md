## Why

A router today picks children by order or by rotation. Neither mode reads the request itself, so a gateway can't send code review to one model and casual chat to another under a single virtual model name. The brainstorm of 2026-08-19 settled a third mode: a judge model classifies each request and the router follows the branch whose rule matches. The flow screens 0 to 7 already live in `designs/recompose.pen` (PR #267), so this change builds the engine, the contract, and the canvas behavior they depict.

## What changes

- `routerPolicySchema` in `packages/contracts/src/gateway-routing.ts` grows a `conditional` variant carrying a judge reference, ordered branches (label, rule, child id), a mandatory else child, and a timeout budget. The judge crosses to the engine as a route node id, never as a spendable account name.
- `ChildPicker` in `packages/engine/src/routing/attempt-walk.ts` goes async, because the conditional pick awaits the judge's answer.
- The walk injects the judge call like an attempt, and the judge inherits the cooldown rules: a cooling judge sends the request down the else branch.
- Conversations stick to the branch they first earned, keyed by a conversation fingerprint, with a per-router toggle to re-judge every request.
- Judge failure, timeout, and no match all land on else. Routing trouble never drops a request.
- Server-state turns follow the `wouldRotate` chained-turn precedent and refuse a branch change.
- The mode sentence joins `router-modes.ts` and `nameOfRouterMode` gains `conditional`.

## Locked decisions

The maintainer brainstorm of 2026-08-19 locked the decisions below, recorded under the "Conditional router (2026-08-19)" heading of `BRAINSTORM-NOTES.md`. Where a discovery brief sharpens a decision, the entry cites the brief by its path under `discovery/`. The gate-1 review adjusted several entries, and each entry records its adjusted form inline.

1. **A mode, not a node (alternative A).** Conditional joins failover and round-robin as the third mode of the single router node. Gate 1 settled the pill's anatomy: the drawn screens introduce a real pill component, and `nameOfRouterMode('conditional')` returns `Conditional` to match `Failover` and `Round-robin`. The `?` stays a decorative leading glyph inside the pill and never enters the mode string, so names, inspector sentences, and refusal bodies stay clean. Chaining stays free. The brainstorm eliminated a separate node type (alternative B), because it would fork the locked single-mode router and mode pill rule.
2. **One constrained classification call decides each request.** The judge receives the branch labels, the branch rules, and the request tail, then answers with one branch label. A broken answer earns one retry, and a second broken answer lands the request on else. A timeout budget of about 3 seconds lands on else too, so routing trouble never drops a request. `discovery/technical-research.md` (section 2) sharpens the call: each dialect constrains the answer with its own enum mechanism rather than prompt discipline. `discovery/acceptance-references.md` (section 2) widens "broken" to cover multiple labels, empty completions, refusals, and truncation. Its section 3 starts the clock at dispatch, covering the wait for the first byte. Section 4 of `discovery/technical-research.md` adds a guard: the walk memoizes the decision, so retried children can't multiply judge calls.
3. **The judge is a real binding.** An account plus a provider model serves as the judge, resolved under the same custody, cooling, and health rules as any target. Fast, cheap models judge best, and the inspector says so. `discovery/technical-research.md` (section 3) sharpens the shape: the stored policy references the judge by route node id, because `packages/contracts/src/engine-routing.ts` keeps account names from crossing to the engine child. That shape also gives the judge its cooling entry for free, since the engine keys cooling by route node address.
4. **Every conditional router carries a permanent else branch.** No match, a judge error, a cooling judge, and a timeout all land there, following the OpenAI If/else "Else" branch. `discovery/acceptance-references.md` (section 1) adds a sharpening: the label set handed to the judge excludes else, so an answer of else counts as broken. And `discovery/technical-research.md` (section 1) shapes else as a named policy field, so the schema itself refuses a router without one.
5. **Conversations stick by default.** A conversation keeps the branch it first earned, keyed by a conversation fingerprint, so the prompt cache survives and mid-conversation behavior stays stable. The per-router toggle "Re-judge every request" opts out. A server-state turn follows the `wouldRotate` chained-turn precedent and refuses a branch change even under the toggle. `discovery/acceptance-references.md` (section 6) sharpens the fingerprint: an explicit client key beats a content hash, and the hash reads only content that stays stable across turns. `discovery/technical-research.md` (section 8) bounds the pin store with an idle expiry, keyed like the engine's other per-router state. Gate 1 paired the toggle with a sentence keyed like `modeSentences`, naming the prompt-cache cost of re-judging and the server-state exception.
6. **Version 1 rules are natural language only.** Each branch pairs a short label with a free-text rule. Deterministic conditions such as regex, token counts, and headers stay out, and belong to a future judge-free rule mode. `discovery/acceptance-references.md` (section 7) supplies the acceptance angle: each branch's rule text travels in the classification request, and editing a rule changes the request.
7. **Wire rules speak the canvas language (alternative A).** Each branch cable carries its rule pill, and the serving branch flows green like any live cable. The brainstorm eliminated alternative B, slot rules: rule rows with their own ports inside a tall card, which swallowed the router's silhouette. It also eliminated alternative C, a prompt panel, which left the canvas bare and hid every rule in the inspector. `discovery/mobbin-references.md` backs the choice: wire previews (Lindy, Twenty, Zapier) beat in-card rule rows (Writer, ManyChat) for canvas economy. Gate 1 adjusted the cable grammar in three ways. Else no longer hangs dashed: it rests like every idle cable, and a quiet "Else" pill in the `text-ink-secondary` tone says its fallback role. No new stroke vocabulary lands. Green keeps its existing meaning, a claim about now: the branch that carried the current request pulses live and cools to resting after the traffic memory. A sticky pin never tints a cable, and pin visibility lives in the inspector rows instead. And the rule pill anchors at about 0.35 of the cable path, leaving the midpoint to `CableFailureChip`. Its text caps at a width derived from `COLUMN_PITCH` minus the card width, and the full rule stays a press away.
8. **The judge rides as a satellite node (alternative E).** A small round node sits above the router, tied by a dotted line from a shoulder port. The distinct silhouette says advisor, not target. The brainstorm eliminated four placements. A side cable to a full card reads as a target lookalike. A docked badge hides health. A sub-port below crowds the child row, and an inbound-wire chip collides with rule pills. `discovery/mobbin-references.md` notes that no surveyed product draws its classifier as a satellite, so the design critique weighs its legibility on screens 5 to 7 rather than lean on outside precedent. Gate 1 kept the intent and trimmed the cost. A scale glyph dies at 11 pixels at minimum zoom, so the node wears a single-stroke mark or no glyph. The round silhouette plus the router tint says advisor. Cooling still turns the satellite amber, but no per-second countdown badge rides the canvas. A `StatusChip` with `tone="attention"` carries the cooling state on the card, and the remaining window lives in the inspector.
9. **The branch label is the classification token.** The judge answers with the label itself, so naming a branch writes the judge's vocabulary. A dropped cable births a draft branch, amber until it holds a name and a rule. The label pill opens the same inline editor as virtual model naming, the Ditto reference. An empty label fills itself from the rule text, following Customer.io's derived wire labels. `discovery/acceptance-references.md` (section 8) sharpens the consequence: a rename changes the judge prompt, so it counts as a semantic edit rather than cosmetic polish.
10. **The full rule lives in a "Branch rule" sheet.** Inspector rows show a one-line rule preview, and the sheet holds a label field, a routes-to line, and a wide textarea. The brainstorm eliminated in-panel editors as too cramped, and accordions as a poor fit for long free text. Gate 1 moved the destructive act out of the sheet. "Delete branch" lives on the branch row, in the `ContextMenu` the child rows already carry, confirmed through `ConsequenceDialog`. The dialog's body names the real cost: requests that matched this rule fall to else.
11. **Router depth stays capped at 4.** `ROUTER_DEPTH_LIMIT` in `packages/contracts/src/gateway-routing.ts` already holds the cap, so chained judges stay bounded and one request meets at most four of them.

## Design-system gap analysis

The project instructions name the Claude Design project "recompose-design-system" as the Tailwind source of truth. That project holds zero synced files today, so nothing exists to sync this analysis against. The analysis therefore runs against the repository's Tailwind usage and the drawn screens 0 to 7 in `designs/recompose.pen` (PR #267). The tokens live in `apps/desktop/src/renderer/src/app/styles/theme.css`, and `discovery/code-map.md` grounds the component citations. Paths below sit under `apps/desktop/src/renderer/src/pages/gateway-canvas/` unless spelled out.

- **The conditional mode pill.** A real component now, per gate 1. The router card in `ui/router-node/router-node.tsx` prints its mode as plain text through `nameOfRouter` and `childTally`, so the pill with its decorative leading `?` glyph is new. `nameOfRouterMode('conditional')` returns `Conditional`, matching `Failover` and `Round-robin`, and the glyph never enters the mode string. The mode option and its sentence join `lib/router-modes.ts`, which carries two modes today. One build-time verification item rides along: the three-option `SegmentedControl` must fit the narrowest inspector.
- **The re-judge toggle and its sentence.** `Switch` in `shared/ui` covers the control. New copy rides with it: a sentence keyed like `modeSentences`, naming the prompt-cache cost of re-judging and the server-state-turn exception. The toggle and its sentence land in the router inspector beside the mode choice.
- **Rule pills riding branch cables.** `ui/binding-cable/binding-cable.tsx` hangs a single piece of furniture on a cable today: the press-to-reveal `CableFailureChip`, positioned through `EdgeLabelRenderer` at the midpoint. A rule pill is new: an always-visible label that rides the cable, coexists with the failure chip, and opens the rename editor. Gate 1 fixed the geometry: the pill anchors at about 0.35 of the path, so the failure chip keeps the midpoint. Pill text caps at a character count derived from `COLUMN_PITCH` minus the card width, with `truncate` plus a title and a press-to-reveal for the full rule. `discovery/mobbin-references.md` carries the Attio caution that wire labels must stay attached to their cable at canvas zoom levels.
- **The green flowing chosen cable and the resting else.** The flowing half exists whole. `lib/cable-standing.ts` paints `live` and `served` in green with a `cable-pulse` animation, and `lib/cable-traffic.ts` cools a served reading back to rest after a minute. Gate 1 dropped the dashed idle else cable, so no new stroke vocabulary lands. Else rests like every idle cable, and its quiet "Else" pill in the `text-ink-secondary` tone says its fallback role. A sticky pin never tints a cable. Pin visibility lands in the inspector rows instead, as a pin mark and a per-branch count.
- **The round judge satellite and its dotted tie.** Nothing on the canvas anticipates this one. `NodeCard` offers two silhouettes, `rounded` and `chamfered`, and nothing small or circular. Edges draw as solid bezier `BindingCable` paths between column ports, so the dotted tie and the shoulder anchor are both new. Gate 1 dropped the scale glyph, which dies at 11 pixels at minimum zoom. The node wears a single-stroke mark or no glyph, and the round silhouette plus the router tint says advisor. Three pieces land here: a satellite silhouette, a dotted tie edge, and a shoulder port, plus an optional single-stroke mark.
- **The satellite's seat in the tidy layout.** `lib/tidy-layout.ts` seats every card in a column counted out from `COLUMN_PITCH`. The satellite needs its own rule: an offset from its router's seat, never a column of its own, so the tidy act keeps advisor and router together.
- **The satellite on the minimap.** `ui/canvas-minimap/canvas-minimap.tsx` paints nodes through its `roleFills` record and wires through `wirePaths`. The satellite needs a fill entry there, and the dotted tie needs a dotted class in `wirePaths`, so the map never shows an orphan judge.
- **The satellite as an inspector subject.** `ui/gateway-canvas-page/canvas-subjects.ts` resolves a selection into an inspector subject. Gate 1 settled that the satellite is a focusable node with its own subject, so keyboard focus reaches the judge and the drawer can speak its health.
- **The cooling state and its tokens.** Still the widest gap, because it crosses the process boundary. No gateway-canvas file mentions cooling: the engine keeps that standing in `packages/engine/src/routing/cooldown-ledger.ts`, and it never reaches the renderer today. Traffic outcomes cross as request readings, and cooldown windows don't. Gate 1 settled the token assignments: cooling takes `--color-attention`, and the draft state keeps `--color-cable-draft`, both already in `theme.css`. `cooling` joins every enumerated standing union, and the exhaustive `Record` maps in `lib/cable-standing.ts` force each paint to answer it. The canvas needs no countdown: a `StatusChip` with `tone="attention"` carries the state, and the inspector prints the remaining window.
- **The draft-branch amber state.** The strongest precedent. Draft cables already paint amber through `stroke-cable-draft`, and drafted cards dash their frames. Two additions remain. The draft standing must cover a stored router's fresh branch until it holds a label and a rule. And the save gate in `lib/model-draft.ts` must learn that a conditional draft also needs a judge binding.
- **The "Branch rule" sheet.** The shell exists: `Sheet` and `SheetActionSlot` live in `shared/ui`, and `ui/connect-sheet` already composes them on this page. `TextField` and `FieldRow` cover the label field and the routes-to line. The hole is the textarea: no multiline text primitive exists anywhere in the renderer. The wide rule field therefore lands as a new shared primitive, with the textarea precedents in `discovery/mobbin-references.md` (Sana, Langdock, Mistral, ElevenLabs) as reference. Gate 1 moved "Delete branch" out of the sheet: it lives in the branch row's `ContextMenu`, confirmed through `ConsequenceDialog`. The dialog's body names the cost: requests that matched this rule fall to else.
- **Inspector rows with one-line rule previews.** `ui/router-inspector/router-child-rows.ts` builds each row from the stored table, and `RouterChildList` renders and reorders them by mode. The row shape carries no label, no rule text, and no pin fact. Sticky conversations surface here: a pin mark and a per-branch count, never a cable tint. The else row can't move or leave, and it says why through the `inertReason` pattern that `SegmentedControl` already carries, rather than a control that goes missing without a word. And `spoken-rank.ts` announces order-based ranks, which read wrong for branches a label names, as `discovery/code-map.md` records.

Every new piece composes from the existing theme tokens: cooling takes `--color-attention`, the draft state keeps `--color-cable-draft`, and no screen asks for a color family `theme.css` doesn't carry.

## Capabilities

### New capabilities

None. The conditional mode extends the existing router capability rather than standing beside it.

### Modified capabilities

- `routers`: a third mode joins failover and round-robin, with a judge binding, labeled branches, a permanent else branch, and sticky conversations.
- `engine`: the attempt walk picks children asynchronously and treats the judge as a real binding under the same custody and cooling rules as any target.
- `gateway-canvas`: the mode pill shows `Conditional` behind a decorative `?` glyph, branch cables carry rule pills, and the judge rides above the router as a satellite node.

## Impact

- The contracts package changes shape, so every consumer of `routerPolicySchema` re-checks against the new discriminated union.
- Making `ChildPicker` async ripples through the walk's call sites in the engine.
- No behavior changes for failover or round-robin routers: the new mode is additive.
- The renderer work lands against settled designs, so screens 0 to 7 in `designs/recompose.pen` bound the canvas impact.
