# Brainstorm decisions

Locked interactively with the maintainer on 2026-08-08, before the candidate panel ran. The panel's approaches must respect every decision here; the open questions at the end are theirs to answer.

## Locked

1. **Topology draws engine truth only.** The canvas renders the gateway, its virtual models, and each model's single target. No router nodes: routers stay a separate later feature, and the left-to-right layout keeps a column free for them. The design template's full chain (gateway, virtual model, router, targets) stays the north star, not this slice's scope.
2. **The canvas shows only wired nodes; a cable dropped on empty canvas opens a picker.** Stored accounts do not float unwired and no palette tray exists. Dropping a dragged cable on empty space opens a compact picker of stored accounts (grouped as in the existing `OptionList`); the picked account materializes as a target node at the drop point, already wired. A missed drop becomes an add, never a silent cancel. Esc during any drag cancels it.
3. **The plus affordance creates a draft virtual model node in place.** A bare gateway draws an automatic wire ending in a plus. Pressing it, or dragging from the gateway's port to empty space, drops a connected draft Virtual Model node and opens the inspector with the name field focused. Definition completes in the inspector (name, alias, provider model); binding completes with the cable gesture of decision 2. No drawer detour.
4. **Cables are first-class objects.** A cable takes selection on press; the inspector then shows the binding (target and real model). Dragging a cable's endpoint onto another compatible node rebinds. Delete unbinds a selected cable. The one-target rule means a new cable dragged from an already-bound virtual model rebinds it, and the old cable falls.
5. **The live layer stays out of v1, but the minimap and zoom controls ship.** The canvas ships static topology plus the status the engine already exposes: gateway running state and per-target standing as pin and cable colors. The maintainer revised this decision on 2026-08-08 after picking React Flow: the library ships MiniMap and Controls as ready components, so the design template's bottom-right map and bottom-left zoom tools join v1, restyled to the template. Flow animation, per-cable metric labels, the metrics status bar, and undo defer to later slices and enter the rider ledger.
6. **Nodes drag freely, positions persist per gateway, and a tidy control restores the automatic arrangement.** New nodes are born at their auto-layout position. The persisted layout is renderer-owned state, not gateway config.

7. **The shipped target policy holds, and rider #117 closes as superseded.** Every stored account kind (subscription, key, aggregator, local) stands as a target in the canvas drop-picker, exactly as `accountsStandingAsTarget` and the shipped `targets.feature` spec it. Whether a target can answer stays a per-request decision. The rider closes with that reasoning rather than silently.
8. **Every drag gesture has a dragless twin.** The technical research flags drag-only binding as a WCAG 2.2 SC 2.5.7 failure (F108). The plus affordance and picker serve as the single-pointer path for every binding a cable drag can create, keyboard reaches nodes and cables, and binding outcomes announce through a live region. This is a constraint on every candidate approach, not a stretch goal.

9. **Delete on a selected virtual model node removes the definition after a confirm dialog.** Cable deletion (unbind) stays confirmation-free. Undo and redo stay out of v1 and enter the rider ledger.
10. **A draft node abandoned mid-definition survives.** It stays on the canvas in a visibly draft treatment, holds across deselection, inspector close, and leaving the screen, exactly like the shipped `useHeldDraft` behavior, until the person completes or explicitly deletes it.

11. **The interaction layer adopts `@xyflow/react` 12.11.2 in full (candidate A).** React Flow owns viewport, pan and zoom, node drag, edge rendering, and connection drag. Nodes and cables render as custom types wrapping the existing `node-card` and `dot-grid` vocabulary, so the design system keeps owning the pixels. The maintainer picked A over the hand-rolled and hybrid candidates on 2026-08-08; the panel's three write-ups and scores live in `candidate-panel.md`. The choice lands in an ADR alongside the attribution decision and the transitive license sweep.
12. **The plus affordance lives persistently on every source port, in every state.** An amendment to decision 3, ratified at gate 1 from the design-critic pass. The gateway's plus opens the draft virtual model; a virtual model's plus opens the drop-picker. A wired gateway never loses its add path, and the single-pointer twin of decision 8 stays real.
13. **Node tint splits by element.** The card frame carries the role tint (teal gateway, blue virtual model, purple target, orange reserved for router). The kicker glyph chip carries the account-kind tint. Locked at gate 1 to resolve the collision the design-critic found between the template's role tints and the shipped account-kind tints.
14. **A broken binding keeps its cable and lands on a ghost target node.** When a target leaves the registry, the cable terminates on a dashed ghost node labeled as removed. Repair is the same cable gesture as any rebind. Locked at gate 1.

## Questions the candidate panel answered

The panel resolved the open questions recorded before it ran: the library question (decision 11), position persistence following the `panel-width` pattern as renderer-owned per-gateway state, the drag machinery coexisting with `usePressAway` through React Flow's `onPaneClick` taking that hook's job, and the drop-picker hosting the untouched `OptionList` over `targetGroups` while drafts keep flowing through `useModelDraft` and `useHeldDraft`.
