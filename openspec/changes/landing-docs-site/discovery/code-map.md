# Code map

- `openspec/changes/landing-docs-site/proposal.md` (no FSD layer (change record)) — symbols: Locked decisions, Capabilities, Impact. Locks the decisions the map answers to: the site lives at apps/web, TanStack Start carries Fumadocs, the build is static on Cloudflare, and release one carries landing plus a first docs set.
- `openspec/changes/landing-docs-site/specs/website/spec.md` (no FSD layer (capability spec)) — symbols: Requirement: The public site serves as files, Requirement: One application holds both public surfaces, Requirement: The hero reveals the scene under the pointer. The three requirements the implementation must satisfy, including the ban on importing the desktop app and the reduced-motion still hero.
- `openspec/changes/landing-docs-site/manifest.md` (no FSD layer (change record)) — symbols: tier, phase, branch. Pins tier full, phase discovery, and branch worktree-landing-docs-site for this cycle.
- `pnpm-workspace.yaml` (no FSD layer (workspace root)) — symbols: packages, allowBuilds, minimumReleaseAge, minimumReleaseAgeExclude. The apps/* glob already admits a second application, but minimumReleaseAge 4320 means any fresh Fumadocs or TanStack Start release needs an explicit exclude line; GAP: no apps/web directory exists today, so every site file is new.
- `package.json` (no FSD layer (repository gates)) — symbols: lint:fsd, lint:boundaries, lint:dead, lint:dup, lint:spell, lint:prose, lint:stories, lint:hig, lint:licenses, typecheck:workflows, typecheck:root-configs. lint:fsd hardcodes steiger apps/desktop/src/renderer/src, and both typecheck scripts shell tsc through pnpm --filter @recompose/desktop, so widening the gates to a second application edits this file first.
- `turbo.json` (no FSD layer (task graph)) — symbols: tasks, build, typecheck, dev, lint, test. build depends on typecheck and lists outputs dist/** and out/** only, so the static site's emitted directory has to join that list or every CI run rebuilds it uncached.
- `apps/desktop/package.json` (no FSD layer (workspace member manifest)) — symbols: @recompose/desktop, build, dev, typecheck, typecheck:web, imports. The template the new site manifest mirrors: turbo task names, the split typecheck, and the #* subpath imports map; GAP: no fumadocs, @tanstack/react-start, or wrangler dependency exists in any manifest in the repository.
- `apps/desktop/tsconfig.web.json` (no FSD layer (TypeScript config)) — symbols: extends, include, paths. The browser-side project the site's own tsconfig copies, and the single tsConfig the dependency-cruiser gate resolves imports through.
- `tsconfig.strict.json` (no FSD layer (TypeScript config)) — symbols: noUncheckedIndexedAccess, exactOptionalPropertyTypes, verbatimModuleSyntax, erasableSyntaxOnly. The shared strictness base every workspace extends; the site inherits it unchanged.
- `tsconfig.root-configs.json` (no FSD layer (TypeScript config)) — symbols: extends, typeRoots, include. Typechecks root-level .ts config files through the desktop node_modules typeRoots, so a site config written in TypeScript lands under this project.
- `.oxlintrc.json` (no FSD layer (repository gates)) — symbols: settings, tailwindcss, entryPoint, ignorePatterns. The Tailwind entry point is the single desktop stylesheet path, so a second Tailwind root gets no class validation until this key admits it; routeTree.gen.ts is already ignored globally.
- `.oxfmtrc.json` (no FSD layer (repository gates)) — symbols: sortTailwindcss, stylesheet, sortImports. Class sorting resolves against the one desktop stylesheet path, the same single-stylesheet assumption the linter makes.
- `.dependency-cruiser.cjs` (no FSD layer (boundary gate)) — symbols: renderer-isolated, desktop-not-into-engine, headless-scope, engine-only-contracts, no-orphans. Every boundary rule keys on ^apps/desktop/ paths and one tsConfig at apps/desktop/tsconfig.web.json, so the spec's rule that the site must not import the desktop app becomes a new forbidden rule here.
- `knip.json` (no FSD layer (dead-code gate)) — symbols: workspaces, entry, ignore, ignoreDependencies. Dead-code detection is per workspace with explicit entry lists, so the site needs its own block for route files and the generated route tree.
- `.jscpd.json` (no FSD layer (duplication gate)) — symbols: threshold, minTokens, ignore. Threshold sits at zero over apps and packages with minTokens 50, so hero or layout code ported next to a desktop equivalent has to differ outright or be shared.
- `probity.config.ts` (no FSD layer (TDD gate)) — symbols: defineConfig, enforceTdd, files. The rule glob is apps/*/src/**, so a new application's src falls under the edit-time test-first gate the moment it exists, with no config change.
- `hig-doctor.config.json` (no FSD layer (design gate)) — symbols: ignore. lint:hig runs hig-doctor over apps at the root, so a second application enters the HIG gate automatically while the desktop package's own lint:hig stays scoped to its renderer.
- `cspell.json` (no FSD layer (spelling gate)) — symbols: dictionaries, ignorePaths, ignoreRegExpList, useGitignore. lint:spell runs over ** and the ignoreRegExpList already skips base64 runs, which is why embedded media never tripped the gate in the prototype.
- `cspell-words.txt` (no FSD layer (spelling gate)) — symbols: affordances, acyclicity, actool. The committed accept list the recompose-words dictionary reads; new site and documentation vocabulary lands here through the PR diff.
- `.vale.ini` (no FSD layer (prose gate)) — symbols: BasedOnStyles, MinAlertLevel, Vocab, Packages. The rule block binds the [*.md] glob only, so GAP: Fumadocs content authored as .mdx sits outside every prose rule until a section names that extension, and no .mdx file exists anywhere in the tree today.
- `.vale/styles/config/vocabularies/recompose/accept.txt` (no FSD layer (prose gate)) — symbols: (?i)api, (?i)css, (?i)ui. The Vale accept list the Vocab key points at; brand and product nouns the landing copy introduces land here.
- `lefthook.yml` (no FSD layer (local gates)) — symbols: pre-commit, pre-push, protect-main, fsd, stories, prose. The local hook order every site commit passes: boundaries, fsd, dead, hig, dup, spell, prose, fmt, typecheck on commit, plus the story check on push.
- `steiger.config.ts` (no FSD layer (FSD gate)) — symbols: defineConfig, fsd, fsd/forbidden-imports. The FSD linter config is path agnostic, so the site's src root joins the gate through the lint:fsd script argument rather than through this file.
- `.claude/workflows/check-stories/check-stories.mts` (no FSD layer (story gate)) — symbols: uiComponent. The uiComponent regex is anchored on ^apps/desktop/src/renderer/src/, so a site ui/ component ships unstoried unless that pattern widens.
- `.claude/workflows/check-licenses/check-licenses.mts` (no FSD layer (license gate)) — symbols: allowlist, LicenseAudit. The license allowlist the whole dependency tree must satisfy, which every new Fumadocs and TanStack Start dependency passes through.
- `.github/workflows/ci.yml` (no FSD layer (CI)) — symbols: changes, check, prose, coverage-upload, ci-success. The changes job filters code as everything outside docs, designs, and *.md, the prose filter matches *.md only, and coverage-upload names three fixed lcov paths, so a fourth workspace touches all three.
- `.github/workflows/release.yml` (no FSD layer (CI)) — symbols: build, draft. Produces the dmg, exe, AppImage, and deb assets a draft release carries, the artifact the landing page download must point at; GAP: no deployment workflow for the site exists in .github/workflows/.
- `apps/desktop/src/renderer/src/app/styles/primitives.css` (app) — symbols: --white, --gray-950, --blue-500. Tier one of the two-tier token scheme, the raw palette; the site needs these values and they currently sit inside the one application the spec forbids it to import from.
- `apps/desktop/src/renderer/src/app/styles/theme.css` (app) — symbols: --font-sans, --color-ink, --color-surface-content, --color-surface-card. Tier two, the Tailwind 4 @theme layer the site reproduces; GAP: --font-sans resolves to a system stack and no @font-face rule exists anywhere in the tree, so the brand typeface has no wired source.
- `apps/desktop/src/renderer/src/app/styles/main.css` (app) — symbols: @import 'tailwindcss', app-drag, app-no-drag. The Tailwind entry point the site's stylesheet mirrors, minus the Electron-only drag regions and the transparent window background.
- `apps/desktop/src/renderer/src/app/router.tsx` (app) — symbols: createAppRouter, AppRouterOptions. The router factory and the @tanstack/react-router module registration the site's TanStack Start router follows.
- `apps/desktop/src/renderer/src/app/routes/__root.tsx` (app) — symbols: Route, RouterAppContext. The typed-context root route whose shape the site's own root route copies for the Fumadocs layout.
- `apps/desktop/src/renderer/src/app/main.tsx` (app) — symbols: createAppRouter, createQueryClient, RouterProvider. The mount sequence, stylesheet import first then providers, which the site's entry repeats without the query client since no route fetches at runtime.
- `apps/desktop/src/renderer/src/app/query-client.ts` (app) — symbols: createQueryClient. Query client factory mounted in main.tsx; a static site needs no runtime fetching, so this is a wiring reference rather than a dependency.
- `apps/desktop/src/renderer/src/app/routeTree.gen.ts` (app) — symbols: FileRoutesByFullPath, FileRoutesById. The generated route tree that oxlint, oxfmt, cspell, and knip all ignore by name; the site emits the same artifact and needs the same ignores.
- `apps/desktop/electron.vite.config.ts` (no FSD layer (build config)) — symbols: tanstackRouter, tailwindcss, defineConfig. Shows the plugin set the site's Vite config reuses, the router plugin plus the Tailwind 4 plugin, with the Electron wrapper dropped.

- `apps/desktop/src/renderer/src/pages/home/ui/home-page/home-page.tsx` (pages) — symbols: HomePage. The folder-per-component layout with browser test and story siblings that every new site ui/ component must match.

- `apps/desktop/src/renderer/src/shared/ui/brand-mark/brand-mark.tsx` (shared) — symbols: BrandMark. The existing brand mark component; the site needs the same marks but cannot import them, so this is the source the port reads rather than a dependency.
